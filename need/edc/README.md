# 필요성 · 이용성(E·D)과 연결성(C) 지표

청주시 기준 **② 이용성**(E1·E2·D1·D2)과 **① 공원조성 가치 중 C1**(녹지축 거리)을 계산한다.
지표 정의는 `docs/청주_장기미집행공원_중간보고서.pdf` 2-3 (가)를 따른다.

> 이 폴더 밖은 고치지 않는다. 결과는 `need/out/indicators_edc.csv` 하나로만 넘긴다.

## 지표

| 지표 | 산식 | 출처키 · tag |
|---|---|---|
| E1 버퍼 인구 | 공원 경계 + 버퍼(`presets.yaml` buffer_m) 안 인구. 100m 격자를 면적 비율로 나눠 더한다 | SGIS-2024 · 실자료 |
| E2 취약인구 비율 | 버퍼 안 격자마다 소속 행정동의 (0~9세 + 65세 이상) ÷ 총인구를 붙이고 인구 가중 평균. 버퍼에 거주 격자가 없으면 소속 동 값 | MOIS-2026-10 + SGIS-2024 · 실자료 |
| D1 서비스권 밖 인구 비율 | 기존 공원(OSM) 유치거리 합집합 밖의 버퍼 인구 ÷ 버퍼 인구 | SGIS-2024 + OSM · 대체자료 (기존 공원이 OSM) |
| D2 생활권 1인당 공원면적 | 공원이 속한 생활권의 1인당 **조성**면적(㎡/인). 결정면적은 `edc_wide.csv`에 참고로 둔다 | PARK2030-T11-2 · 실자료 (도심생활권 배정은 가정) |
| C1 녹지·수변축 거리 | 공원 경계 → 수변생태축 하천 또는 300ha 이상 큰 산림(산악축) 중 가까운 곳(m). 산림은 토지피복지도 활엽·침엽·혼효림을 이어 붙인 덩어리 | OSM(하천) + EGIS-LC-2025(산림) · 대체자료 (녹지축 도면이 아님) |
| (표시) 지역 유형 | 버퍼 인구밀도 ≥ 1만 명/㎢ → 밀집, ≥ 1,500명/㎢ 또는 토지피복 주거지역 ≥ 15% → 주거, 토지피복 공업지역 ≥ 10% → 산업(겹치면 함께), 나머지 기타(농촌·산림). **점수에 넣지 않는다**(용도지역은 개발압력 P2와 겹침) | SGIS-2024 + OSM · 가정 |
| C1_near · river_adjacent | C1 ≤ 500m · 하천 100m 이내 (1/0). 사업성 `need.csv`가 받는다 | OSM · 가정 |
| 신규 수혜 인구 | 조성하면 처음 서비스권에 들어오는 인구 = E1 × D1 | SGIS-2024 + OSM · 대체자료 |

- **생활권 배정**: 공원과 가장 많이 겹치는 행정동이 `downtown_dongs`(중앙·성안·탑대성·사직1·사직2·사창·운천신봉·우암)에 있으면 도심생활권, 아니면 소속 구의 생활권으로 본다. 도심 동 목록은 청주형 15분 도시 일상생활권 구축계획(1차, 2025) 보도에서 가져왔다. 2030 계획 원문의 동 목록은 확인하지 못했다(가정).
- **중간보고서 수정 필요**: 1-1의 "도심생활권 1인당 공원면적은 7.4㎡로 최저"는 표 11-2와 맞지 않는다. 7.4㎡는 청원생활권의 조성면적(최고)이고, 도심생활권은 조성 1.7㎡·결정 11.1㎡로 최저다.
- 기준값(유치거리, 플래그 경계, 하천 목록, 생활권 표)은 `code/params.yaml`에만 있다.

## 결과 (2026-11-18, SGIS 격자 기준)

- 39/40곳을 산정했다(5 어린이공원152는 경계가 없어 미산정). 버퍼 인구가 0인 공원은 없다.
- **인구 자료 검증**: 행정동 43개의 격자 인구 합을 주민등록 인구와 비교했다. SGIS는 r = 0.99, 평균 오차 12%이고 WorldPop은 r = 0.73, 평균 오차 60%였다. WorldPop은 도심을 2~5배 많게 잡았다(성안동 주민등록 6,076명 → SGIS 6,457명, WorldPop 17,242명).
- 그래서 도심 공원의 E1이 크게 줄었다. 근린공원8은 17,960명에서 5,866명, 신규 수혜 인구는 3,369명에서 1,246명이 됐다. 신규 수혜 인구 1위(근린공원8)는 그대로다.
- E2는 0.19(복대1동)~0.55(현도·낭성면) 사이다.
- 지표 쌍의 |r|은 모두 0.7 미만이다(가장 큰 값: E1↔D1 spearman −0.47). 다섯 지표를 모두 쓴다.
- C1 녹지축 대리를 50ha에서 300ha 산림으로 올렸다. 50ha로는 C1_near = 1이 28/39곳이라 변별력이 없었다. 300ha로 바꾸니 17/39곳이다. 산림을 토지피복지도로 바꾼 뒤에도 17/39곳이다. 녹지축 도면을 받으면 교체한다.
- 지역 유형(토지피복지도 기준): 기타 26 · 주거 8 · 밀집 3 · 산업 1 · 주거+산업 1. 서원구 농촌의 소공원52~55가 주거에서 기타로 바뀌었다. OSM은 이 일대를 주거용지로 넓게 그렸지만 토지피복지도의 주거지역은 2~10%뿐이고, 인구밀도도 170~540명/㎢이다.

## 대시보드 — `EDC_지도.html`

내려받아 더블클릭하면 열린다(인터넷 연결 필요: 배경지도 OSM, Leaflet). GitHub 웹에서는 코드만 보이니 **Download raw file**로 받는다.

- **지도**: 공원 40개소를 고른 지표의 5분위 색으로 칠한다. 켜고 끌 수 있는 레이어는 인구 격자, 기존 공원 서비스권, 기존 공원, 유치거리 버퍼, 수변생태축, 녹지축 산림, 구 경계다.
- **필터**: 지역 유형(밀집·주거·산업·기타) 칩, 생활권 선택
- **공원 카드**: "반경 ○m 안에 ○명, 이 중 ○%가 아동·고령, ○명은 지금 공원 서비스 밖" 같은 근거 문장과 지표별 값·태그(실자료/대체자료/가정)
- **표**: 열 머리를 누르면 정렬된다. 행을 누르면 카드와 지도가 그 공원으로 이동한다.

다시 만들기: `python build_edc.py && python build_page.py` (`need/out/edc_map.json` → `need/edc/EDC_지도.html`)

## 실행

```bash
pip install shapely pyproj pyyaml rasterio numpy scipy
cd need/edc/code && python build_edc.py && python build_page.py
```

결과는 `need/out/indicators_edc.csv`(긴 표, 점수 계산용)와 `need/out/edc_wide.csv`(공원별 가로표, 검토용)이다.
WorldPop 원본(10MB)은 저장소에 들어 있다. 새로 받아야 할 때만 아래 명령을 쓴다.

```bash
cd need/edc/data/raw/worldpop && curl -O https://data.worldpop.org/GIS/Population/Global_2000_2020_Constrained/2020/BSGM/KOR/kor_ppp_2020_UNadj_constrained.tif
```

## 결과 양식

`site_id, indicator, value, unit, source_key, tag`. tag는 `실자료 / 가정 / 미산정 / 대체자료` 중 하나다.
공원 경계는 `biz/data/vworld/parks.txt`를 읽기만 한다(복사·수정 금지).
