# 필요성 · H 위해(열환경) 지표

청주시 기준 **① 공원조성 가치 중 H 위해**(현재 더위 · 조성 시 냉각 편익)를 40개소 전부 계산한다.
결과는 `H_지도.html`(한 파일, 더블클릭으로 열림)과 `data/H_results_40parks.csv`.

> 이 폴더 밖은 고치지 않는다. 다른 파트에는 `data/H_results_40parks.csv`의 `site_id, lsta, heat_grade, benefit, benefit_rank`만 넘긴다.
> 에너지 파트(`energy/`)와 같은 위성 자료를 쓰지만 목적이 다르다: 여기는 **공원별 순위(필요성)**, 에너지는 **청주 전체 냉각량(참고)**.

## 지표

| 지표 | 산식 | 출처키 · tag |
|---|---|---|
| lsta 현재 온도 편차 | 공원 중심 300m 버퍼의 여름 지표온도 중앙값 − 청주 범위 평균 (℃) | LS-2024-25 · 실자료 |
| ndvi 녹지 정도 | 300m 버퍼 NDVI 중앙값 | S2-2024-25 · 실자료 |
| pop300 주변 인구 | 300m 버퍼 인구 합 (명) | GHSL-POP-2020 · 대체자료 |
| cool 예상 냉각 | `b × max(0, 목표 NDVI − ndvi)` (℃). b·목표값은 `code/params.yaml` | 청주 전역 회귀 · 가정 |
| benefit 냉각 편익 | `|cool| × pop300` (명·℃) | — |
| heat_grade 열환경 등급 | lsta 5분위, 1 = 가장 더움 | — |
| H 점수 · 등급 | 현재 더위 백분위와 편익 백분위의 가중 평균 → 상위 30% 상 · 하위 30% 하 | — |

## 실행

1. 좌표: `code/geocode_vworld.py`의 `KEY`에 본인 V-World 키를 넣고 실행 → `park40_geocoded.csv` (키는 저장소에 올리지 않는다)
2. 위성값: `code/gee_heat_h.js`를 GEE Code Editor에 붙여 넣고 Run → 콘솔의 `RESULT_JSON` 줄을 `data/gee/`에 저장
3. 대시보드: `H_지도.html`은 결과가 안에 들어 있어 그냥 연다. 파이썬판은 `cd code && pip install -r requirements.txt && streamlit run app.py`

## v2 보완 (2026-11-16 오후) — 폴리곤 · 실측 계수 · 안정성

v1(점+300m 원, 공간 회귀 −10.1)의 세 가지 약점을 고쳤다. **v2가 기준이고 v1은 참고로만 남긴다.**

| 고친 것 | v1 | v2 | 왜 |

| 공원 경계 | 지번 좌표 + 300m 원 | V-World 공원 폴리곤 39곳(`biz/data/vworld/parks.txt`, 5번만 등가원) | 원은 길쭉한 공원·하천변 생태공원에서 엉뚱한 땅을 포함 |

| 냉각 계수 | −10.1 (공간 회귀: 녹지 많은 곳이 시원하다) | **−4.6** = 청주 2013–16→2023–25 녹지가 실제 변한 픽셀의 기울기 −2.1(늘어난 곳)~−7.0(줄어든 곳) 중간 (`energy/data/gee/gee_change_output.txt`) | 공간 상관은 인과가 아니라 과대 추정. 전후 실측이 에너지 파트와도 일치 |

## v2.1 (2026-11-18) — H에서 인구 제외

- 인구는 지표표의 **E 노출 축**(인구밀도·고령)이 맡으므로 H에 다시 곱하면 이중 계산이다. `h_engine.py`의 `use_pop: False`가 기본: H 점수 = 일대 현재 더위 백분위 × 0.5 + 냉각량(℃) 백분위 × 0.5. 대시보드 '인구 반영' 체크를 켜면 v2(편익 = 냉각 × 인구)로 되돌아간다.
- 결과: 상 12 · 중 16 · 하 12, 확정 25/40. 상위 5곳(소공원76·근린공원8·소공원169·소공원77·어린이공원194)은 그대로 전부 확정이고 순서만 바뀜(인구를 빼니 복대동 소공원76이 1위). 인구를 넣었을 때와 등급이 같은 공원 29/40 — 달라지는 11곳은 주로 외곽의 더운 소공원(인구 없어 v2에선 중·하)이며, 그 차이는 E 축에서 반영된다.

## 결과 v1 (2026-11-16 오전, 참고)

- 40/40곳 산정. 청주 범위 여름 평균 지표온도 34.4℃ (Landsat 48장 · Sentinel-2 8장).
- 수목형 조성 시 평균 냉각 −3.2℃. 편익 상위: 소공원76(복대동, +8.2℃, 7,517명) · 근린공원8 · 역사공원199 · 어린이공원144 · 소공원169.
- 등급: 상 12 · 중 16 · 하 12. 시 1단계인 근린공원8은 상, 문화공원4는 하(이미 숲이라 냉각 여지 없음 → 열 외 사유).
- 검증: 대시보드 계산을 pandas로 재현해 등급 수·1위 일치 확인. 근사 좌표(동·리 중심)로 돌린 11-14 결과 대비 29곳이 1.5km 이상 이동했으므로 11-14 값은 폐기.

## 가정 · 한계

- 인구는 SGIS 격자가 아니라 GHSL 2020 (전역 자료, 실제보다 낮게 나올 수 있음).
- 청주 평균은 행정경계가 아닌 사각형 범위로 계산.
- 버퍼는 공원 폴리곤이 아니라 중심점 300m. 폴리곤(도시계획정보 SHP)을 받으면 교체.
- 냉각 계수 b는 11-14 청주 전역 회귀값을 그대로 씀. "해제"라는 표현은 쓰지 않는다.
