> **먼저 읽을 문서: [06_전체루트.md](06_전체루트.md)** — 전체 루트 확정안

## 1. 무엇을 하려는가
`energy/`는 "공원을 조성하면 **지표온도**가 몇 도 내려가나"까지 계산했다(청주 위성 실측 계수만 사용).
여기서는 그다음 질문에 정량적으로 답한다.

> **"그 온도 저감으로 주변 건물의 여름 냉방 에너지가 얼마나(kWh·원·tCO₂) 줄어드나?"**

`energy/`는 2026-11-14 1차판에서 전력(kWh)까지 계산했다가 **근거가 약해 폐기**했다(`evidence/evidence_E_energy.md` E5).
폐기 이유 세 가지를 하나씩 메우는 것이 이 작업의 뼈대다.

| 1차판에서 약했던 고리 | 왜 문제였나 | 이번에 메울 방법 |
|---|---|---|
| ① 지표온도(LST) → 기온 | 해외 비율 0.08~0.6배, 7배 이상 차이 | 청주 기상 관측소 + 같은 날 Landsat으로 **청주 비율**을 직접 구하거나, 기온을 거치지 않는 경로(②)를 쓴다 |
| ② 기온 → 전력 | 도시 전체 평균(%/°C, W/인)을 공원 주변 국지 변화에 적용 | 청주 **건물별 월 전력 사용량**과 그 건물 주변 위성 온도를 직접 맞대어 **청주 계수**를 만든다 |
| ③ 1인당 냉방전력 등 2차 통계 | 기사 인용, 1차 통계 아님 | 국토교통부 건물에너지(지번 단위 월별)·공동주택 관리비 자료 등 **1차 공공자료**만 쓴다 |

## 3. 진행 상황 (2026-11-20)
| 단계 | 상태 | 막힌 것 |
|---|---|---|
| R1 조성 사례 지표온도 | **완료(1차)** → 08 | 공식 준공연도 대조는 서울식물원 1건만 |
| R2 지표온도 → 기온 비율 | 대기 | 기상자료개방포털(AWS 분 단위) **로그인 필요** |
| R3 기온 → 건물 냉방전력 | 대기 | 건축HUB 건물에너지(지번별 월 전력) **로그인/신청 필요** |
| R4 공원별 kWh | 대기 | R2·R3 결과 |
| R5 탄소 | 계수 확보(2023 전력 배출계수 0.4173 tCO₂eq/MWh) | R4 결과 |
| R6 공동주택 검증 | 대기 | 공동주택관리정보(K-apt) **API 키 필요** |

### 원래 계획
1. **준비**: 방법 검토, 자료 목록, 결정 사항 정리
2. 조성 전후 사례 측정(05): 사례 공원 경계 수집 → GEE로 전후·거리별 지표온도 → **공원 조성 실측 계수·퍼짐**
3. 자료 받기: 청주 건물 에너지·건축물대장·기상 관측 → `data/raw/`
4. 기온 반응 학습: 건물 주변 위성 온도 ↔ 건물 냉방 전력 (`code/`)
5. 공원별 적용: `energy/` 저감 범위 안 건물 × 계수 → kWh·원·tCO₂ (시나리오 범위)
6. 검증·지도: 다른 방법(시뮬레이션·문헌 범위)과 비교, 지도·표

## 4. 폴더 규칙 (저장소 공통 규칙을 따름)
- 숫자 상수는 코드에 쓰지 않고 `code/params.yaml`에만 둔다. 출처는 문서에 적는다.
- 결과는 단일값이 아니라 **시나리오 최소~최대**로 낸다(몬테카를로 없음).
- 바꿀 때마다 저장소 `CHANGELOG.md`에 한 줄 남긴다. 공원 열쇠는 `site_id`.
