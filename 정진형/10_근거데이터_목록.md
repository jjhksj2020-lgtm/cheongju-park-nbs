# 10. 에너지·탄소 저감 알고리즘의 근거 데이터 (= 학습 데이터) 목록

> 목적: "도심지·나대지에 이런 공원이 생기면 인근에 이만큼 에너지·탄소가 줄어든다"를 계산하는 **하나의 알고리즘**을 만든다.
> 예측 모델에서 학습 데이터가 결과를 결정하듯, 이 알고리즘의 모든 계수는 아래 실측 데이터에서만 나온다. 가상·가정 데이터는 쓰지 않는다.
> 숲 공원(이미 숲인 곳)은 조성해도 녹지가 그대로라 계산 대상이 아니다. 숲 → 개발 사례는 **같은 관계를 반대 방향에서 검증하는 데이터**로만 쓴다.

---

## 0. 알고리즘 한 줄 요약

```
공원 조성 → [①] 녹지 증가가 만드는 지표온도 변화 (공원 규모·거리별)
         → [②] 지표온도 → 기온 환산
         → [③] 기온 → 건물 냉방 전력 변화
         → [④] 공원 주변 범위 안 건물(세대)에 합산 → kWh/년
         → [⑤] × 전력 배출계수 → tCO₂/년
```

| 단계 | 정하는 계수 | 근거 데이터 | 상태 |
|---|---|---|---|
| ① 녹지 → 지표온도 | 공원 안 ΔLST, 거리 감쇠, 규모 보정, 계절 | D1 (학습) · D2 (반대 방향 검증) · D3 (청주 적용 확인) | **확보·분석 완료** |
| ② 지표온도 → 기온 | 환산 비율 k, 시간대(저녁 피크) | D4 | 미확보 (로그인 불필요) |
| ③ 기온 → 냉방 전력 | 1 °C당 냉방 전력 β | D5 | 미확보 (공개 여부 확인 필요) |
| ④ 공원별 합산 | 영향 범위 안 건물·세대 수 | D6 | 일부 확보 (공원 경계 39곳) |
| ⑤ 탄소 | 전력 배출계수 | D7 | 확보 |

## D1. 학습 데이터 ① — 실제로 "나대지·공사지 → 공원"이 된 전국 72곳의 전후 지표온도

| 항목 | 내용 |
|---|---|
| 정하는 것 | 공원 조성 시 지표온도 변화 크기, 거리 감쇠, 면적 보정, 계절 |
| 원천 1 | 공공데이터포털 「전국도시공원정보표준데이터」(15012890) 18,376곳 |
| 원천 2 | Landsat 8·9 Collection 2 Level 2 (USGS), 여름(6~9월) 지표온도·NDVI, 2013~2025 |
| 원천 3 | ESA WorldCover 2021(토지피복), JRC GHSL SMOD 2015(도시 여부) |
| 표본 뽑는 규칙 | 중부권 5,000㎡ 이상 3,231곳 → 위성 "새 녹지"(2013~15 NDVI < 0.25 → 2022~24 > 0.5, 도시지역, 0.54ha 이상) 597곳 → 공원 좌표와 맞댄 81곳 → 정착 연도 2016~2022·NDVI 상승 ≥ 0.25·0.4ha 이상 **72곳** |
| 표본 특성 | 신도시(동탄·배곧·송도·청라·세종·내포·미사 등) 위주, 위성 새 녹지 면적 0.4~4.9ha(중앙 0.57ha), 조성 전 NDVI 0.18 → 후 0.56 |
| 측정 방식 | 장면별로 10km 주변 중앙값을 빼서 날씨·기후 상승 제거(LSTa) → 공원 안·바깥 고리(0~100·100~200·200~300·300~500m)의 전후 변화 → **같은 사례 300~500m 고리 대비**(주변 동반 개발 상쇄) |
| 핵심 결과 (여름) | 공원 안 **−0.96 °C**, 0~100m **−0.43 °C**, 100~200m −0.13 °C, 200~300m 0 · 감쇠 길이 약 60m · NDVI 1.0당 약 −3.0 °C |
| 규모 | 1ha 미만 −0.5~−0.8 °C / **1ha 이상 −1.5 °C(포화)** |
| 계절 | 여름만 냉각(−0.96). 봄 +0.39, 가을 +0.11, 겨울 +0.25 → **냉방 계산은 6~9월만** |
| 점검 | 정규화 없이 계산해도 본 결과 −1.03 °C(정규화 −0.96)로 같음 |
| 파일 | 목록 `data/r1_matched_parks.csv` · 연도별 NDVI `data/r1_yearly_ndvi_raw.txt`·`data/r1_onset.csv` · 사례 `data/r1_cases.json` · 결과 `data/r1_did_raw*.txt`, `data/r1_did.csv` · 코드 `code/r1_*.js`, `code/r1_*.py` · 설명 `08_R1_조성사례_실측.md` |
| 한계 | 위성 열센서 해상도 약 100m(1ha) → 1ha 미만은 작게 측정될 수 있음 · 공식 준공 연도와 맞댄 것은 서울식물원 1곳 · 사례별 편차 큼(IQR ±0.9 °C), 중앙값으로만 사용 |

## D2. 검증 데이터 ① (반대 방향) — 전국 도시 숲 일부가 개발된 561곳의 전후 지표온도

| 항목 | 내용 |
|---|---|
| 역할 | 학습에 쓰지 않음. **"녹지가 바뀌면 주변 온도가 바뀐다"는 관계가 반대 방향에서도 같은 모양인지** 확인 |
| 원천 | Landsat 8·9(위와 같음), Google Dynamic World(2023~24 건물 확률), GHSL SMOD |
| 표본 뽑는 규칙 | 2013~15 NDVI > 0.65(숲) → 2022~24 < 0.35, 건물 확률 > 0.4, 도시지역, 바로 옆에 남은 숲, 2ha 이상 → 전국 1,092곳 → 주변 300m의 30% 이상이 남은 숲 578곳 → 장면 충분 **561곳** |
| 핵심 결과 (여름) | 개발된 자리 **+4.56 °C**, 0~100m **+1.99 °C**, 100~200m +0.41, 200~300m +0.13 · NDVI 1.0당 +8.5 °C |
| 검증 결론 | 영향이 **100~200m에서 대부분 사라지는 모양이 D1과 같다** → 알고리즘의 영향 범위 근거 확인. 크기는 녹지가 줄 때가 훨씬 크다(비대칭) → 공원 조성 계산에는 **D1(녹지 증가) 값만** 쓴다(보수적) |
| 파일 | 탐지 `data/r3_forestloss_patches.txt` · 공원 매칭 `data/r3_forestloss_park_match.txt` · 요약 `data/r3_did_summary.txt` (원값은 GEE 자산 `r3_did`) · 코드 `code/r3_*.js`, `code/r3_analyze.py` · 설명 `09_반사실_사례데이터.md` |
| 참고 | `energy/` 녹지 손실 계수 −7.01 °C/NDVI와 같은 크기 → 기존 청주 계수가 실제 개발 사례로 확인됨 |

## D4. 학습 데이터 ② (미확보) — 지표온도 → 기온 환산

| 항목 | 내용 |
|---|---|
| 정하는 것 | 지표온도 1 °C 변화가 기온 몇 °C인지(k), 저녁 피크(오후 5~7시)·밤 시간대 공원 효과 |
| 후보 | 서울시 S-DoT 도시데이터 센서 환경정보: 서울 전역 1,170대(주거·상업·공업·도로·공원), 1시간 단위 기온 최소·최대·평균, 지상 약 3m (공공데이터포털 15157504, 서울 열린데이터광장) |
| 방법 | Landsat 촬영일(오전 10시 반) 같은 시각 센서 기온 ↔ 센서 위치 지표온도 → k. 공원 근처/먼 센서의 시간대별 기온 차 → 저녁 효과 |
| 대안 | 기상청 AWS·ASOS (기상자료개방포털, 로그인 필요) |
